# 仪表盘样式与设备回归

日期：2026-10-19。

本文前半部分保留首轮实现记录；最新的固定排序、配置卡和内存卡调整见文末“后续调整”。

## 实现

- 页面标题、底部导航、布局编辑提示与保存错误文案由“概览”统一改为“仪表盘”。内部导航枚举、通知目标与偏好存储键保持兼容。
- 参照提供的图片采用浅灰背景、大圆角白色卡片、蓝色主操作、浅灰内嵌区与轻阴影；深色使用独立语义色。
- 顶部状态卡整合公网 IPv4、地区、运行时长、当前配置和启停按钮。保留公网刷新、异常原因、Core 重启与代理繁忙时的禁用逻辑。
- 手机的网络速度卡包含上传／下载两个面板；展开屏为两个独立卡片。两条曲线分别使用各自的真实样本和峰值，保留累计量、缺失数据与绘图失败反馈。系统大字号时面板上下排列，避免单位被拆行。
- 出站模式改为横向选择；新增独立 VPN 开关、实际服务状态和策略组入口。配置卡展示更新时间、到期日及已知的订阅用量；实时连接、最近请求分别进入活动页对应标签。内存卡明确展示 Core 实时内存。
- 复用现有宽度断点，并考虑系统字号；卡片高度随内容增长。滚动区保留底部导航空间，图标按钮具有无障碍名称，状态包含文字。
- 保留拖动排序和前移／后移菜单。旧 `traffic` 合并到速度卡，旧 `duration` 合并到状态卡；已有顺序优先，缺失的新卡片追加，不删除偏好数据。
- 未新增依赖。新增三个 SVG，并修正为可随 ArkUI `fillColor` 着色的填充路径。

改动主要位于 `DashboardPage`、三个 Runtime 展示卡片、Dashboard 模型／常量／工具、Runtime 曲线工具、PreferenceRepository、浅深主题及文案资源，以及相关测试。

## 参考图与现有能力的对应

本轮为界面调整，所有正式数据继续来自现有 Store 与服务。图中的 IP 住宅／机房分类和质量评分、内网 IP／局域网代理、第三方网站可用性探测、DNS 查询总数、应用进程内存尚无对应接口，本轮未新增这些后台能力，也没有以固定数值代替。

服务状态展示真实的 Core、VPN、配置及公网查询状态；内存只展示已有的 Core 数值；策略组使用组名首字符，没有引入外部头像或品牌图片。

## 设备与验证方式

使用本机已有的 **Mate X6** 和 **Mate 90 Pro 模拟器**，HarmonyOS 7.0.0 / API 26、x86_64。

正式包在两台设备上检查了未配置／Core 不支持的真实状态。现有 Go 核心只有 ARM64 预编译库，因此运行中的流量、配置、策略组和开关反馈通过临时隔离快照验证：仅替换 DashboardPage 的 Store／服务导入，使用实际页面、组件、主题和应用导航，不写入订阅数据库、不启动系统 VPN。模拟流量不代表真实网络测量。

每次临时构建都按字节恢复正式页面并移除临时源码；最终 signed／unsigned HAP 的 `ets/modules.abc` 均检查不含 `DashboardQaFixture`、`DashboardQaRuntime` 或示例 IP。

## 后续调整：固定排序、配置与内存

- 移除仪表盘布局编辑入口、拖动和前移／后移操作，并删除排序偏好的读写代码。固定使用默认顺序；已有偏好数据留在本地但不再影响展示，配置列表自己的排序不受影响。
- 窄屏上传／下载面板最小高度从 176vp 降到 132vp，曲线高度从 56vp 降到 32vp，内边距从 14vp 降到 12vp。标准字号实测面板约 133vp，大字号仍允许内容撑高并上下排列。
- 配置卡按参考图展示：标题右侧刷新和详情入口；名称旁切换配置；更新时间／剩余天数；已用百分比／用量和总量；蓝色波浪已用段、灰色剩余段和末端圆点。刷新与切换复用 ProfileStore，保留下载校验、应用和错误处理，操作期间禁用重复请求。长名称最多两行；到期、未知额度和本地配置单独处理。
- 新增 AppMemoryService，通过系统异步接口 `hidebug.getAppNativeMemInfoAsync()` 每 5 秒获取 UI 进程 PSS，KB 转字节。内核继续读取独立 VPN 宿主返回的 Mihomo 统计值。卡片显示两者之和、双色比例条和对应数值，均按 1024² 换算为 MB、保留一位小数。任一数据缺失时合计显示“—”，已获取的分项继续显示；详情入口解释统计口径。
- 修复 ArkUI Builder 参数保存初始数值导致应用内存图例停留在占位符的问题，图例直接观察组件状态，随真实内存采样更新。没有引入依赖、权限或原生核心改动。

后续验证证据位于 `.hvigor/dashboard-details-qa/`，与首轮截图分开保存。应用 PSS 来自模拟器实际 API；订阅、运行流量和内核数值仅在临时验证包中注入，最终正式包不含这些快照。

- 单元测试：entry 91/91、proxy_core 1/1 通过，覆盖固定顺序、响应式跨度、内存缺失和零值、比例／总和、波浪边界及到期天数。已移除过时的拖动排序测试。
- 最终正式构建 `assembleHap --no-daemon` 通过编译、打包和签名；signed／unsigned HAP 的 `ets/modules.abc` 均确认不包含验证类或示例 IP。
- Mate X6 展开与 Mate 90 Pro 标准字号：配置卡信息和内存图例完整显示，应用／内核／合计在同一 UI 快照中核算通过，刷新忙碌态、更新时间、配置切换、长名称、过期、未知额度和本地配置完成检查。
- Mate X6 模拟折叠（1080×2440）：切换到单列，速度面板实测 132.8vp；Mate 90 Pro（1280×2832）为 132.9vp。两台深色下的波浪、数值和内存占比条可读，Mate 90 Pro 特大字号下速度面板上下排列，配置和内存图例没有重叠，卡片可滚动到导航栏上方。
- Mate X6 的订阅刷新失败场景保留当前选择并解除忙碌态；Mate 90 Pro 的内存详情入口可打开，实际 PSS 连续采样后图例与合计同步变化。

代表性截图：`x6/refresh-complete.png`（展开屏配置与内存）、`x6/fold.png`（窄屏速度）、`mate90/profile-long-expired.png`（长名称和过期）、`mate90/memory-verified.png`（特大字号深色内存）。`check.py`、`adaptive.py`、`font.py` 保存本轮设备检查流程。

结束前两台均恢复跟随系统主题并安装最终正式包，Mate 90 Pro 恢复标准字号／默认显示缩放，Mate X6 恢复展开竖屏。正式包再次验证：在内核不可用时应用 PSS 分别读到 82.6 MB／72.2 MB，合计和内核保持占位，未将缺失项当作零；证据为两台目录中的 `production-memory.png`。最终 `git diff --check` 通过。

仍未验证真机 VPN/TUN、真实订阅下载和物理折叠。模拟器运行态中的内核数值是隔离快照，应用内存为系统实测；两项统计口径不同，合计并非系统对整个应用包所有进程的内存核算。
