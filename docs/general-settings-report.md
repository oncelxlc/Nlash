# 常规设置实现与验证

日期：2026-10-22。

## 范围与实现

设置首页新增“常规”二级页，复用现有返回导航、主题、字体缩放和滚动头部。参考 [FlClash](https://github.com/chen08209/FlClash) 的常规设置语义及本机 `NFlClash/lib/views/config/general.dart`、`lib/common/task.dart` 实现。

仅包含入站、连接和内核；未增加启动与后台、请求与更新、日志与诊断分组。

| 项目 | 行为 |
| --- | --- |
| 端口、局域网代理 | 控制 HTTP/SOCKS 混合监听端口；0 关闭监听；默认 7890，仅本机访问，开启局域网代理后允许局域网连接。端口占用时恢复原设置。 |
| 外部控制器 | 复用固定内核的 REST API，仅监听 `127.0.0.1:9090`；首次开启生成随机密钥，可修改。 |
| 认证 | 首次开启生成账号和密码，可修改；包括 loopback 在内均需认证，不继承订阅的认证豁免。 |
| 测试链接 | 复用现有应用偏好与节点/策略组测速入口，校验 HTTP(S) 地址。 |
| 统一延迟、TCP 并发、查找进程 | 映射内核配置；进程查找使用 always/off，实际识别能力受系统权限限制。无运行宿主时的预览测速也读取已保存设置。 |
| 自动关闭连接 | 节点真正改变时按开关决定是否断开连接；配置恢复和重复选择同一节点不主动清连接。 |
| 仅统计代理流量 | 使用固定内核的代理专用计数器；切换统计范围后重建界面采样基线和曲线，重新计数。 |
| IPv6 | 同时控制内核解析、TUN IPv6 地址及平台默认路由；运行中切换会短暂重连，失败尝试恢复原设置及代理。 |
| Hosts | 每行 `域名 = IP 或域名`，支持多个 IP、IPv6 和内核域名通配模式；同名覆盖不区分大小写，保留订阅的其他条目。 |
| 追加系统 DNS | 从 HarmonyOS 默认非 VPN 网络读取，追加而不替换订阅上游，并监听网络变更；地址不持久化。 |
| Geo 低内存模式 | 映射 `memconservative` / `standard`。 |

常规内核覆写以 `core/work/nlash-general-settings.json` 原子保存，不修改订阅文件。运行中保存保留模式、节点选择与平台 TUN；IPv6 切换例外，需重建系统 TUN。内核启动失败时仍可读取、保存设置以修复端口冲突，下次启动应用。

未更改内核版本固定值或 C ABI。复用内核控制器使 Go 模块补齐其已有的间接依赖 `github.com/ajg/form`；没有新增前端依赖或自行实现另一套控制 API。已有本地签名配置改动保持不动。

## 真机验证（2026-10-22）

设备型号 `ICL-AL20`，ARM64，系统报告 `OpenHarmony-7.0.0.105`。使用当前 signed HAP 覆盖安装成功，保留原应用数据。通过 USB 操作设备，以同一局域网中的电脑发送真实代理请求；控制器仅借助 USB 转发访问本机监听端口。

| 验证项 | 结果与证据 |
| --- | --- |
| 局域网代理关闭 | 电脑连接手机 `7890` 端口被拒绝；USB 转发到手机 loopback 后，HTTP CONNECT 与 HTTPS 请求成功。 |
| 局域网代理开启 | 电脑经手机的 HTTP、SOCKS5 混合代理均完成 HTTPS 请求，返回 `200 OK`。 |
| HTTP 认证 | 无凭据返回 `407`，错误密码返回 `403`；正确凭据 CONNECT 成功，目标 HTTPS 返回 `200 OK`。 |
| SOCKS5 认证 | 无认证方法不能直接建立连接；错误密码返回 `01 01`，正确密码返回 `01 00`，随后连接成功且目标 HTTPS 返回 `200 OK`。 |
| 本机认证 | 经 USB 转发连接手机 loopback，无凭据仍返回 `407`，不存在本机认证豁免。 |
| IPv6 开关与重连 | 开启时内核报告 IPv6、TUN IPv6 地址和新的 FD；真机可 ping 通 `fdfe:dcba:9876::1`。关闭后重建 TUN，内核不再报告 IPv6 地址，该地址不再应答。 |
| IPv6 出站 | 蜂窝网络下，以明确的 IPv6 字面地址通过内核建立 TCP 隧道，再按目标域名校验证书，HTTPS 返回 `200 OK`；运营商 IPv6 DNS 也实际返回了解析结果。 |
| 系统 DNS 随网络切换 | VPN 运行期间，蜂窝网络查询记录的上游为 `udp://[2409:8062:2000:2::1]:53`；切回 Wi-Fi 后自动变为 `udp://192.168.3.1:53`。再次切到蜂窝网络后，新的有效域名解析成功。 |
| 系统 DNS 开关对照 | 独立临时配置只保留不可用上游 `127.0.0.1:1`。关闭追加后查询明确失败；重新开启后同一有效域名立即返回实际 A 记录。排除了订阅中的其他上游掩盖问题的情况。 |

IPv6 **普通应用流量完整经过 TUN 尚未通过验收**：浏览器对测试目标的请求未在内核请求记录中出现，未得到有效的 TUN IPv6 流量证据；用于读取路由的临时原生探针被设备拒绝执行。上述地址、重连和 IPv6 出站成功，不能代替 IPv6 默认路由与应用流量接管的验证，也不足以把浏览器现象归因为本次代码缺陷。

原订阅与规则模式已恢复，核对 7 个策略组的选择均未变化。临时配置单独创建并删除，未编辑原订阅文件。

收尾复核：恢复原 Wi-Fi，VPN 已关闭且系统不再存在 `vpn-tun`；局域网代理、认证、控制器、IPv6、追加系统 DNS 均恢复关闭，端口仍为 7890，电脑再次连接手机 LAN 端口被拒绝。4 个测试浏览器标签已关闭，保留原有 2 个标签；USB 端口转发列表为空，临时 HTTP 服务已停止，设备探针和本地凭据副本已清理。

本轮没有修改应用实现代码；仅补充设备验证记录，并通过 `git diff --check`。本地测试证据保存在忽略目录 `native-core/out/real-*`，凭据不写入本报告。
