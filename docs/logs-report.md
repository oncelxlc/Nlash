# 日志功能与验证记录

日期：2026-10-23。

## 功能

- 设置 → 日志：仅开启捕获时显示，位于“主题”之后的同一分组；独立二级页面显示时间、等级和正文，使用懒加载列表。
- 设置 → 常规 → 日志：捕获开关及调试、信息、警告、错误、静默五档等级。
- 默认信息等级、关闭捕获；选项写入现有常规设置文件，旧文件自动补齐默认值。
- 捕获 Mihomo 日志及现有内核生命周期/诊断事件，不采集系统 HiLog。日志等级作为最低捕获等级，静默不记录。
- 单独修改日志选项不重新解析配置、不重建监听器；其他常规设置继续沿用原有应用与回滚流程。
- 最多保留最近 500 条、64 KiB 正文，单条正文超过 2048 字节时按 UTF-8 边界截断。记录仅驻留内存，不自动写文件或输出到系统 stdout。
- 关闭捕获立即清空内核缓冲区及日志页面缓存，并隐藏设置中的日志入口；重新开启后从空记录开始。等级切换保留已有记录，内核宿主进程退出后清空。离开日志页面或应用进入后台时停止界面轮询，内核捕获独立运行。已导出的文件不受影响。
- 搜索匹配正文、中文/英文等级和本地时间，忽略英文大小写及关键词首尾空格。
- 导出点击时的搜索结果，无搜索时导出全部现存记录。内容为 UTF-8，按时间正序排列；通过系统文件保存选择器选择位置。
- 文件名读取应用名称并使用本地时间，例如 `Nlash_2026-10-23_08-09-05.log`。

## 改动范围

- ArkTS：设置入口与导航、常规日志分组、新增 `LogsPage`、`LogService`、日志模型/常量/工具函数及回归测试。
- Go：有容量限制的内存日志缓冲区、日志快照命令、常规设置校验与持久化、内核日志订阅及回归测试。
- ARM64 预编译库已重建并同步。未新增依赖、修改版本固定值或更改 C ABI。
- 保留已有 `build-profile.json5` 本地修改；未创建分支、提交或推送。

### 真机发现的问题与修复

600 次请求首次全部成功，但日志页面停留在 364 条并持续出现 `Core 控制请求超时`。原控制通道将整个快照放入单个 CommonEvent，项目的 1 MiB 响应限制高于 [平台单次 data 的 64 KB 限制](https://raw.githubusercontent.com/openharmony/docs/master/zh-cn/application-dev/reference/apis-basic-services-kit/js-apis-inner-commonEvent-commonEventPublishData.md)，日志正文及 JSON 元数据合计超限后无法发送。

修复范围为控制通道常量、响应信封类型、协议工具、Extension 发送端和 UI 接收端。大响应按 8 Ki UTF-16 单元拆分，最坏 JSON 转义也低于单次 64 KiB；根据请求 ID 独立合并，处理乱序和重复，拒绝冲突或非法分片，缺失分片仍受原请求超时控制。保留 1 MiB 总响应上限、小响应原格式及日志的 500 条/64 KiB 正文容量，不新增依赖或日志落盘。

新增回归覆盖中文/emoji/转义字符、乱序与重复、缺片不提前完成、冲突与非法元数据、请求隔离、最大响应及超限拒绝。修复后 Hypium 125/125 + 1/1、5 个修改的生产 ArkTS 文件 lint、签名 HAP 构建均通过；ARM64 核心未变更。

修复包覆盖安装后，600 次真实代理请求在 6.00 秒内全部返回 200，暂停捕获后页面显示“信息 · 500 / 500 条”，无读取失败或超时。内核宿主 PID 保持不变。500 条数据下再次取消导出通过，重新保存得到 `Nlash_2026-10-23_02-45-08.log`：56000 字节、500 条互不重复的 INFO 记录，均为本轮成功请求，UTF-8、每行格式和时间正序校验通过。
