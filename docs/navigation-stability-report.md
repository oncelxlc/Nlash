# 底部沉浸光感导航稳定性验证报告

日期：2026-09-06。

## 实现范围

- `Index` 统一使用一个底部悬浮 `HdsTabs`，按仪表盘、代理、配置、请求、连接、设置的顺序提供六个入口；不再按折叠状态切换 Side/Bottom 布局。
- 浮动栏使用 `barPosition: End`、`barOverlap(true)`、`adaptToHandedness: true`、`thermoCtrl: true`，材质类型和等级均为系统 `ADAPTIVE`；没有新增自定义模糊、颜色、宽度、握姿监听、权限或依赖。
- 禁用横向滑动切页，并设置 `cachedMaxCount(0, TabsCacheMode.CACHE_LATEST_SWITCHED)`；页面切换后只保留最近页面，避免六页订阅和仪表盘定时器同时常驻。
- `AppNavigationState` 只保留当前 `AppPage`，通知意图与 Tab 点击仍通过 `selectPage()` 选择页面；删除 `NavPathStack`、`AppRoute`、`NavigationLayout`、折叠/窗口监听和旧导航占位组件。
- 六页统一增加 80vp 悬浮导航避让；仪表盘、代理、配置、请求、连接的悬浮按钮及配置编辑器底部操作同步上移。
- 返回行为保持不变：配置编辑器先关闭；其他一级页回仪表盘；仪表盘返回后应用进入后台。

## 尚未覆盖

- 设备接口只提供最终浮动栏位置，不提供本次智感握姿的文字分类；已实际观测左/中/右自动迁移，但无法把居中样本进一步区分为未握持、双手或未知状态。
- 未自动改变系统分屏/浮窗状态，发布前仍需人工检查这两种窗口形态。
- 本轮未重新点击系统通知；通知到仪表盘的既有意图通道保留并通过编译，仍建议发布前做一次通知点击回归。

## 结论

代码、单测、签名构建和可执行真机检查均已完成。旧 Side/Bottom 结论已失效；当前实现统一为六项底部沉浸光感导航，并已在 API 24 展开设备上观测到系统驱动的左、中、右位置变化。分屏/浮窗和通知点击保留为发布前人工验收项。
