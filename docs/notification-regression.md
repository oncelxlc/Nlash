# 通知实现与回归

## 实现

- 应用获得通知权限并进入前台时，由 `EntryAbility` 初始化通知服务。仅当代理为 `ENABLED` 时，使用 UIAbilityContext 申请 `dataTransfer` 长时任务并显示系统实况通知；应用启动但未开启代理时不显示通知。以代理状态为准，Core 状态变化不误撤销仍在运行的代理通知。
- 通知管理位于 UIAbility 进程，流量采样复用既有跨进程控制通道；VPN 和 Core 仍由 `ProxyVpnAbility` 承载。代理运行期间按两秒间隔更新同一系统通知，正文只显示上下行速率，例如 `↑ 1.0 KiB/s · ↓ 2.0 KiB/s`，不拼接运行状态。
- 点击通知携带 `targetPage=dashboard`。入口使用 singleton，冷启动通过待处理导航意图进入概览，热启动通过 `onNewWant` 切到概览。
- 关闭代理或离开运行状态时，立即停止采样并通过发布队列停止长时任务、撤销通知，不创建普通状态通知。采样和任务申请结束时再次检查当前状态，过期结果不再用于更新通知；再次开启代理时创建新任务。UIAbility 销毁时释放任务、通知及事件监听。
- 通知权限检查和任务申请在前台执行；权限检查返回前若应用已退到后台或销毁，不再启动通知服务。
- 不使用普通通知降级。任务申请失败或被取消时记录原因并停止刷新；再次开启代理或进入应用前台时可重试。启动时清理旧版本的普通通知。

## 验证记录（2026-10-17）

工具链：DevEco Studio 6.1.1.300，工程 API 24；系统通知行为使用 API 26 真机验证。

- `assembleHap --no-daemon`：通过，生成签名 HAP。
- `test --no-daemon`：entry 75 项、proxy_core 1 项，共 76 项通过，0 失败、0 错误。覆盖运行、未连接、开启中、关闭中和异常状态的通知可见性，纯上下行速率消息，以及通知点击发生在页面订阅前、订阅后两种导航时序。
- 普通通知实验：同时设置 `isOngoing=true` 和 `isUnremovable=true`，真机仍能划掉通知，故未将这些字段作为常驻方案。
- 应用启动：真机保持代理未连接，启动应用并退到后台后，通知栏没有 Nlash 通知。
- 开启代理：连接后只有一条 `LiveCardSystemView`；UI 树断言其正文为 `↑ 0 B/s · ↓ 0 B/s` 形式，不包含“代理”“运行”“Core”“服务”等状态文字。
- 关闭代理：系统任务 ID 19 停止，通知栏没有 Nlash 通知，也未生成普通状态通知。
- 再次开启代理：创建新的系统任务 ID 20，仍只有一条实况通知，正文仅含上下行速率；未复用已经停止的任务。
- 点击与常驻：从设置页退到后台后点击通知，返回概览且代理保持连接；点击后通知仍存在，单条横向滑动后也仍存在。
- 再次关闭代理：系统任务 ID 20 停止，通知栏再次没有 Nlash 通知。
- 验证结束后，设备恢复为概览前台、代理未连接。

## 平台边界与待测内容

- 通知按代理连接状态管理；数据传输任务仍受系统策略约束，空闲或低流量时可能被取消。此时不创建普通通知，重新开启代理或进入前台可重试；三方接口无法保证通知始终不可清除。
- 当前 API 24 通过 `downloadTemplate` 更新自定义上下行速率，系统模板含进度环。真机实验中删除 `progressValue` 仍显示进度环且更新返回 401；去掉整个模板只显示系统默认任务文案，更新同样返回 401。沿用用户此前暂留系统进度环的选择，保持未完成值 0。
- 此系统模板不显示自定义“暂停”按钮。点击实况通知进入概览后可以暂停；通知服务不再创建无效的暂停 WantAgent。
- 未验证冷进程实际通知点击、长时间锁屏待机、低流量回收策略和后台 Core 重启后的通知恢复；冷启动导航意图由单元测试覆盖。
